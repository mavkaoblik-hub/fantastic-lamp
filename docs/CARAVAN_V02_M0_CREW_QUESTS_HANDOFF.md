# КАРАВАН v0.2 — перший прохід Етапу 0 (23.10.2026)

## Реально реалізовано в основному джерелі Android APK
- `web/caravan_systems.js` — автономна логіка трьох працівників, доручення для трьох чинних вагонів, черга до трьох, часовий прогрес, винагорода один раз після завершення, скасування, повернення.
- `web/gameplay_ui.js` — інтегровані меню екіпажу, журналу завдань та перегляду складу. Дані зберігаються у чинному `state.support` через звичайний `persist()`, не створюючи конкурента існуючому збереженню.
- Три завдання журналу: розвідати станцію, здійснити перший рейс, покращити вагон; винагороди зберігають стан отримання.
- `web/index.html`, `web/style.css` — кнопки з художнього затвердженого атласу, вода, мораль, місткість екіпажу.
- Workflow Android APK пакує оригінальні PNG-вирізки (категорії UI, ресурси, статуси, завдання, валюти) **всередину** APK; онлайн-завантажень для цих ресурсів немає.
- `tests/caravan_systems.test.cjs` — регресійні тести черг, винагород, скасування та відновлення збереження.
- `web/sw.js` — оновлено кеш автономної браузерної версії, вилучено посилання на неіснуючі PWA-іконки.

## Що НЕ реалізовано й не слід називати готовим
- Візуальна анімація проходу персонажів через двері та робочих місць: логіка доручень є, але на сцені ще немає справжніх RGBA-анімацій.
- У чинній сцені, як і раніше, три базові вагони; 14 видів і локомотив L1–L4 потребують окремої інтеграції з перевіреними спрайтами.
- Повна економіка води/моралі та критичні пороги, мапа, події, крафт і інвентар предметів.
- Фактичний тест на фізичному Android-смартфоні; CI не підтверджує поведінку сенсорного екрана.
- Підписання APK постійним релізним ключем, можливість безболісного оновлення замість перевстановлення.

## Приймальний тест на Android
1. Встановити нову debug APK із Actions / CARAVAN-auto-Android-debug-APK.
2. Без Інтернету відкрити меню ЕКІПАЖ, призначити Марку роботу на складі, перевірити, що через приблизно 18 ігрових секунд додається 8 металу.
3. Призначити три доручення в чергу, четверте має бути відхилене. Перевірити скасування та повернення на патруль.
4. Розвідати станцію, відкрити ЗАВДАННЯ, отримати винагороду; повторне отримання повинно бути неможливим.
5. Здійснити один рейс і одне покращення вагона, отримати винагороди за відповідні завдання.
6. Перезапустити застосунок: збереження, черги та отримані винагороди повинні залишитися.
7. Оцінити масштаб значків, горизонтальну компоновку, доступність кнопок, спливаючої панелі та збереження старих можливостей вибору вагонів і поїздки.

Після фізичного тесту можна змінювати статус відповідних пунктів ТЗ із IN_PROGRESS/CODE_READY на DONE; до того позначки DONE не ставити.

## Наступний пріоритет
1. Довести живу сцену екіпажу (переміщення, двері, точні хітбокси, RGBA).
2. Розширити реальні вагони через один каталог без дублювання затвердженої графіки.
3. Три режими камери, мобільні safe areas, повний HUD із критичними порогами.
