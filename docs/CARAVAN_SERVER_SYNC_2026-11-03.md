# D7A: вхід і необов’язкова серверна синхронізація

База: `main` / D7A, `6aedf3b3e4ae3e89dc717d71bd2ae0ed61dcc8e7`.
Гілка `feat/caravan-d7a-integrated-server-safe` на початку роботи збігалася з `main`.

## Поведінка

При першому запуску з налаштованим HTTPS endpoint гра автоматично створює
акаунт і початковий нікнейм `Караван-…`, без форми та підтверджень.
Перед першим запитом вона зберігає випадковий 256-бітний `registration_key`.
Сервер приймає його додатковим полем POST `/v1/players` і за повторним запитом
повертає той самий профіль/код. Втрата відповіді, reload та конкурентні запити
не створюють дублікатів і не витрачають повторно квоту нових профілів.
Legacy-реєстрація лише з nickname лишається сумісною, але не має такого replay.
Секрети на сервері зберігаються лише як хеш access code; міграція БД не потрібна.

Збережений код автоматично перевіряється через `GET /v1/me` при наступному запуску.
401 зупиняє повтори, не створює інший акаунт і не перекриває gameplay.
«Профіль і зв’язок» відкриває лише необов’язкові налаштування: повторне ввімкнення,
ручне відновлення за кодом або вимкнення синхронізації. Явне вимкнення
запам’ятовується навіть до першої реєстрації. Без інтернету гра працює локально;
після відновлення зв’язку актуальне зведення надсилається з урахуванням backoff.

Код і enrollment secret зберігаються окремо від gameplay, у localStorage ключі
`caravan_sync_v1:<HTTPS origin>`. Це bearer credentials: не публікуйте їх.
Зміна endpoint не переносить код іншому серверу. Доступ до цього пристрою/web
origin дає доступ до коду; не додавайте сторонні скрипти до сцени. Якщо
локальне сховище недоступне, акаунт не створюється. Повних хмарних збережень,
email-входу та відновлення після втрати всіх локальних секретів немає.

Надсилаються виключно цілі `metal`, `fuel`, `supplies` у межах 0…1 000 000 000.
Дробові локальні значення округлюються вниз лише в зведенні. Стан екіпажу,
маршрути, інвентар, morale, condition та локальні ключі `caravan_v12`,
`caravan_v09`, `caravan_v07` клієнт синхронізації не змінює.
Відповідь сервера ніколи не підміняє локальний gameplay або ресурси.

Кожне надсилання читає актуальну ревізію, потім поточне зведення ресурсів.
Немає черги застарілих snapshot: після скидання гри беруться поточні ресурси.
Одночасно виконується одна операція. Успішні спроби — не частіше ніж раз на
60 секунд, лише на видимій сторінці (перша перевірка одразу). Запити мають
10-секундний timeout; помилки відкладають повтор із backoff до години,
`Retry-After` сервера також враховується. Конфлікт ревізії не перезаписується
сліпо: наступна спроба знову читає `/v1/me`. Автоматична реєстрація повторює
лише той самий збережений registration_key; новий секрет при мережевій помилці
не генерується. Спочатку оновіть сервер: старий API відхилить додаткове поле,
і клієнт не робитиме небезпечного fallback до неідемпотентної реєстрації.

Вхід на іншому пристрої не переносить прогрес: ресурсне зведення береться саме
з цього пристрою. Для одного профілю варто використовувати один активний пристрій;
паралельні клієнти можуть почергово публікувати різні локальні зведення.

Рейтинг залишається на серверній сторінці `/`. Він містить публічні,
не перевірені сервером зведення (`verification: client_reported`), не доводить
чесність гри. У грі показано стан зв’язку й надсилання, а не вигаданий рейтинг.

## Налаштування HTTPS

1. Розгорніть `server/` за його інструкцією за HTTPS reverse proxy з валідним
   сертифікатом. Залишайте Uvicorn на loopback; не відкривайте його порт напряму.
2. Додайте GitHub Actions repository variable `CARAVAN_SERVER_URL`, наприклад
   `https://api.example.org`. Це публічна адреса, **не секрет**. Дозволено лише
   HTTPS origin: без шляху, query, fragment, імені користувача або пароля.
3. Workflow `caravan-v012-original-android.yml` передає змінну пакувальнику.
   Для локального пакування встановіть таку саму змінну середовища і виконайте
   `python tools/caravan_restore_v012.py build/caravan_v012`.
   `tools/configure_caravan_sync.py <готова-папка-гри>` також може оновити
   конфігурацію після пакування. Результат — `sync_config.json`; джерельний
   конфіг має порожній endpoint і не викликає мережевих запитів до API.
4. У systemd drop-in сервера задайте власний домен і точні origins:

   ```ini
   [Service]
   Environment="CARAVAN_ALLOWED_HOSTS=127.0.0.1,localhost,api.example.org"
   Environment="CARAVAN_ALLOWED_ORIGINS=https://appassets.androidplatform.net,https://game.example.org"
   ```

   Пропустіть browser origin, якщо вебверсія не публікується. Без wildcard,
   `null`, HTTP чи завершального `/`. Вкажіть порт в origin, якщо він нестандартний.
   Перезапустіть сервіс після зміни. Reverse proxy має зберігати потрібний Host
   або передавати localhost; не задавайте wildcard hosts/origins.
5. Перевірте через HTTPS `/health`, реєстрацію, `/v1/me`, PUT snapshot і CORS
   preflight з фактичного web origin та Android. Коди передавайте тільки у
   заголовку Authorization; не в URL, журнал чи workflow variable.

Android зберігає попередній HTTPS appassets origin, package/applicationId і DOM
storage. INTERNET permission додано; mixed content, файловий доступ та довільна
навігація залишаються заблоковані. Нативний allowlist читає той самий конфіг
і дозволяє лише три точні API-шляхи на одному налаштованому HTTPS host/port.
TLS-помилки не ігноруються. Відкривати зовнішні сторінки в цьому WebView не можна.

Під час оновлення APK потрібен сумісний підпис попередньої інсталяції.
Не видаляйте застосунок і не очищайте його дані для обходу конфлікту debug-підпису:
це знищить Android localStorage. Основний debug-пакет має versionCode 4 і той самий applicationId.
Для встановлення поруч використовуйте preview із суфіксом `.syncpreview` —
див. [виправлення конфлікту встановлення](CARAVAN_ANDROID_INSTALL_CONFLICT_2026-11-03.md).

## Перевірки та межі

- `node --test tests/*.test.cjs`: модулі gameplay і синхронізації, зокрема безпечні
  параметри запитів, allowlist, 429, 401, втрачена відповідь, durable storage,
  вимкнення під час запиту, нові ресурси після reset.
- `python -m unittest server.test_caravan tools.test_caravan_sync_config -v`: SQLite/API, точний CORS allowlist,
  preflight, auth errors, конкурентні ревізії, quota та реальний loopback Uvicorn.
- `node tests/caravan_server_browser.cjs`: реальний FastAPI і тимчасова SQLite,
  автоматична реєстрація без форми, повтор втраченої відповіді без дубліката, автоматичний вхід при reload,
  ресурсне зведення й leaderboard, офлайн-старт без підміни прогресу.
  HTTPS origins у браузері локально маршрутизуються Playwright, TLS/DNS
  зовнішнього сервера цим тестом **не** перевіряються.
- `caravan_v012_visual_smoke.cjs` і `caravan_android_touch_smoke.cjs`: поточний
  gameplay, save/reload, чотири мобільні viewport, multi-touch. Це браузерні тести,
  а не виконання APK на фізичному Android.
- Restore перевіряє SHA256 11 вихідних архівів і 103 оригінальні sprites.
- GitHub workflows запускають API/browser тести та збірку/підписну перевірку APK.

Публічний сервер не налаштований і не вважається перевіреним до реальної перевірки
за наданим URL. Фізичний Android-тест входу/відновлення зв’язку потрібен окремо.
