# КАРАВАН: ОСТАННЯ ДОРОГА — v0.13-D5

**Дата:** 28.10.2026 · **Статус:** TESTING · **Напрям:** керування екіпажем всередині потяга під час активного рейсу.

## Проблема

У D1–D4 екіпаж може працювати і відпочивати в інтер'єрах, але нове призначення під час рейсу блокується: стара анімація перепризначення виводить персонажа на перон. Через це управління вагонами під час довгого рейсу обмежене.

## Реалізовано

1. **Внутрішнє переведення без виходу назовні.** У `game/v012_restored/internal_transfer.js` є окрема чиста модель `start / advance / normalize / canStart / occupancy`. При переведенні працівник перебуває в `mode='transferring'`, `inside=1` і має лише внутрішню `location`. `p.transfer` зберігає `fromId`, `toId`, `target`, `progress`, `duration`. Зайнятість зараховується одній, а не двом виробничим кімнатам.
2. **Без подвійного виробництва.** У момент початку переходу `p.job=null` і режим перестає бути `working`; `production.js` не враховує цього працівника, поки не завершиться `advance`. Після завершення в цільовому вагоні задається нове `job.target` і відновлюється `working`. Жодні ресурси чи досвід безпосередньо модулем переведення не нараховуються.
3. **Резервування місткості.** L1 — 1 робоче місце, L2 — 2. `occupancy()` враховує поточних працівників і всі незавершені внутрішні переведення. Спроба зайняти вже зарезервоване місце або повторно запустити перехід блокується.
4. **Взаємодія.** На активному маршруті `assignCrew(target)` тепер викликає `TRANSFER.start()` для вагонів, але **не** запускає зовнішні `walking/exiting`. На картці вагона кнопка показує «ПЕРЕВЕСТИ» або «У ПЕРЕХОДІ». Поточний список екіпажу показує відсоток внутрішнього переходу. На стоянці збережено попередні анімації входу через двері й обмеження місць.
5. **Візуал.** `interior_life.js` відображає перехід тільки в приміщеннях: до половини — в початковому вагоні, після половини — у призначеному, з ослабленням прозорості. Не малюється людина на колії. Це умовне відображення шляху через недоступний гравцеві внутрішній коридор, **а не** повноцінна кадрова анімація переходу через зчеплення.
6. **Сумісність.** `crew_transit.js` не скидає `mode='transferring'` у `aboard` під час руху, зупинки чи події; `transfer` серіалізується в чинному ключі `caravan_v12`, проходить валідацію при відновленні. Якщо вагон або запис пошкоджено, персонаж повертається в безпечний режим очікування всередині локомотива. Зовнішня посадка D2 і старі спрайти не змінені.
7. **Оригінальна графіка.** 103 затверджені спрайти v0.12 та наявні альфа-іконки збережені без замін і дублів.

## Приймальні перевірки

| ID | Критерій | Автоматизація |
|---|---|---|
| D5-01 | Вибір «ПЕРЕВЕСТИ» під час руху запускає внутрішній перехід | Browser |
| D5-02 | Працівник не стає зовнішнім патрулем і не створює другу винагороду | Node + Browser |
| D5-03 | Робоче місце з моменту початку переведення вільне | Node + Browser |
| D5-04 | Цільове робоче місце зарезервовано; переповнення L1/L2 заборонене | Node + Browser |
| D5-05 | Повторний клік або повторне переведення в дорозі не створює дубля | Node |
| D5-06 | Рейс можна поставити на паузу, завершити переведення і продовжити | Browser |
| D5-07 | Перезапуск посеред переходу зберігає прогрес | Node + Browser |
| D5-08 | Після завершення `job.target` і `location.carId` вказують лише на новий вагон | Node + Browser |
| D5-09 | Старі збереження без `transfer`, D1–D4, проходять міграцію | Browser |
| D5-10 | Оригінальні спрайти, pinch, навігація та APK не змінюють візуальний еталон | CI + фізичний Android |

**Автоматичні тести:** `tests/caravan_v013_internal_transfer.test.cjs`, `tests/caravan_v012_visual_smoke.cjs`. GitHub Actions забезпечує підпис debug APK, контроль файлів і browser smoke. Повна фізична перевірка на Android залишається обов'язковою.

## Межі етапу

- Внутрішній перехід моделюється як переїзд між приміщеннями й коротка плавна індикація, без нового анімаційного атласу коридорів.
- Переведення на одноразовий ремонт локомотива під час активного рейсу **не** реалізовано: доступні виробничі вагони.
- Не додаються нові типи вагонів, валюти, ресурси, бої або друга іконка завдань.

## Подальша робота

Перевірити D5 на реальному Android, покращити видимість внутрішнього переходу за допомогою схвалених арт-ресурсів (не змінюючи вагон), а потім перейти до системи втоми, відпочинку й розвитку персоналу.
